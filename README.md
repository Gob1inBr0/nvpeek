# nvpeek

**nv**（NVIDIA）+ **peek**（瞄一眼）——一个贴在 macOS 桌面上的小组件：通过 SSH 免密登录
连接多台远程服务器，随时瞄一眼每张 NVIDIA 显卡的显存占用、利用率，以及每张卡上正在
跑的进程（谁在占卡、跑了多久）。服务器数量不限，随时在设置里增删。

## 功能

- **顶栏常驻小图标**：菜单栏里有一个 GPU 小图标（绿点=至少一台在线），点开就是全部操作：
  显示/隐藏小组件、收起/展开迷你条、立即刷新、切换钉桌面/悬浮、设置、退出
- **直接导入 ~/.ssh/config 里的服务器**：设置里自动列出你 ssh 配置里的所有主机，
  勾选后一键导入，不用手动抄地址；导入后按别名连接，配置里的地址、端口、密钥、
  跳板机全部自动生效
- 钉在桌面层（默认）：和系统桌面小组件同一层，被普通窗口自然遮挡，不挡任何工作内容；
  也可以在设置里改成"悬浮在所有窗口前"
- 迷你模式：点标题栏的收缩按钮，缩成一条只显示各机器空闲卡数的小条
  （如"算力A 5/8"，有空闲是绿色、连不上是红色 ✕），点小条展开；状态会记住
- 全局快捷键显示 / 隐藏：默认 ⌥⇧G，任何界面下按一下整体隐藏，再按一下显示，
  快捷键可以在设置里修改或关闭
- 每台服务器一张卡片：连接状态、空闲卡数量（空闲 5/8）、最近刷新时间
- 每张卡一行：编号（绿=空闲，蓝=在用，红=快满）、型号、温度、显存占用、
  利用率和显存两条进度条（显存超 90% 数字变红）
- 进程列表：每行的显卡号、用户名、程序名、占用显存、已运行时长；鼠标悬停看完整命令
- 刷新间隔可选 2/5/10/30/60 秒（默认 5 秒），支持开机自动启动
- 原生窗口拖动：按住标题栏（或迷你条）拖动，跟手不黏滞；不抢焦点、不占 Dock，位置会记住
- 某台机器连不上时单独显示错误信息，不影响其他机器

## 使用前提

1. 这台 Mac 上已经配好免密登录：终端里执行 `ssh 用户名@服务器地址`（或 `ssh 别名`）
   能直接登录，不用输密码（用 `ssh-copy-id 用户名@服务器地址` 可以配置）。
2. 服务器上有 `nvidia-smi`（装了 NVIDIA 驱动就有）。

## 构建和运行

```bash
./build.sh
open build/nvpeek.app     # 或直接双击 build/nvpeek.app
```

第一次打开会显示"还没有添加服务器"，点右上角齿轮（或"打开设置"）。

**推荐做法：从 ~/.ssh/config 导入。** 设置里有一栏"~/.ssh/config 里的服务器"，
自动列出你 ssh 配置里的全部主机（默认全选），点"导入选中"即可。

也可以"手动添加服务器"：

- 别名：显示在卡片上的名字，可留空
- 用户名、主机：和 ssh 命令一致，例如 root、192.168.1.10；用户名留空时主机填
  ~/.ssh/config 里的 Host 别名（即上面的别名连接方式）
- 端口：默认 22，别名连接时忽略

保存后约 1 秒内就能看到数据。

```bash
NVPEEK_DEMO=1 ./build/nvpeek.app/Contents/MacOS/nvpeek
```

## 它是怎么取数据的

程序用系统自带的 `ssh` 执行一条组合命令，一次往返取回三段数据：

1. `nvidia-smi --query-gpu=...`：每张卡的显存、利用率、温度
2. `nvidia-smi --query-compute-apps=...`：每张卡上的计算进程
3. `ps`：这些进程属于哪个用户、跑了多久

所以对服务器的要求和你在终端里手动执行 `nvidia-smi` 相同：能登录、能看到
nvidia-smi 就能用。个别驱动上普通用户看不到别人进程的显存占用时，会显示"—"。

## 常见问题

**某台服务器一直显示连接失败**
先在这台 Mac 的终端里手动执行 `ssh 别名`（或 `ssh 用户名@主机`），看能不能直接登录。
第一次连接会问是否记录主机指纹，程序会自动记录（等同 `StrictHostKeyChecking=accept-new`），
但如果之前连过同一地址的其他机器，指纹冲突时需要手动处理一次。

**导入列表里没看到某台机器**
检查 `~/.ssh/config`：只有写成具体名字的 Host 会列出（`Host gpu1`），
带 `*`、`?` 或 `!` 的模式（比如 `Host *`）不会列出；`Include` 引用的其他文件会自动展开。
设置窗口每次打开时重新读取，改完配置重开一次设置即可。

**组件被窗口挡住看不到了？**
默认钉在桌面层（和系统小组件一样），普通窗口会遮挡它。三个办法：推开窗口看一眼、
按 ⌥⇧G（默认快捷键）先隐藏再显示会把它带到前面、或在设置里把显示方式改成"悬浮在所有窗口前"。

**怎么改成"迷你小条"常驻？**
点组件标题栏的收缩按钮（第一个小图标），它会缩成一条只显示空闲卡数的小条；
点小条任意位置展开。收起/展开状态会记住，下次启动保持。

**从旧版 GPUWidget 升级，服务器要重新添加吗？**
不用。程序改名后首次运行会自动把旧版本的配置（服务器列表、窗口位置、显示设置）
迁移过来；如果之前设置过开机自启，在设置里重新勾选一次即可。

**提示没有读到 GPU 信息**
服务器上执行 `nvidia-smi` 试试。没装驱动（或不是 NVIDIA 显卡）时就是这个提示。

**开机自启在哪里设置**
小组件右上角齿轮打开设置，勾选"登录 macOS 后自动启动"。取消勾选即关闭。

**怎么退出**
小组件右上角的 ✕ 按钮，或右键菜单里的"退出"。

## 构建说明（写给在这台机器上重新构建的人）

这台 Mac 只装了"命令行工具"（Command Line Tools），没装完整版 Xcode。最新版
27.0 SDK 把 SwiftUI 的 `@State` 改成了宏实现，但宏插件没有随命令行工具一起发布，
直接 `swift build` 会报 `plugin for module 'SwiftUIMacros' not found`。
build.sh 已经处理：检测到 26.5 SDK 存在时自动用它编译，编出来的程序在新系统上
照常运行。装了完整 Xcode 的机器不受此影响。

另外命令行工具没带 XCTest，`swift test` 跑不了；build.sh 会编译运行
`Tests/ManualCheck` 里的校验程序代替（同样的用例）。
